The Core Challenges of Microsecond-Level Latency

In low-latency computing environments such as high-frequency trading and real-time market data processing, response times are now measured in microseconds or even nanoseconds. Traditional approaches typically face three critical challenges:

  • Prohibitively High Technical Barriers: Developers need deep expertise in CPU architecture, compiler optimizations, and often assembly-level programming.
  • Implementation Complexity: Systems must eliminate memory allocation overhead, avoid context switches, minimize CPU cache misses, and control latency jitter — all simultaneously.
  • Poor Development Efficiency: Strategy research is typically prototyped in scripting languages like Python for speed, but production deployment requires a complete rewrite in C++. This not only extends development timelines but creates inconsistencies between backtesting and live trading behavior.

Swordfish: DolphinDB’s Low-Latency Solution

To overcome these challenges, DolphinDB developed Swordfish, a low-latency streaming data processing system. Its core advantages include:

  • Low Technical Barrier: Developers can focus purely on strategy logic using DLang, DolphinDB’s proprietary scripting language. Without managing CPU architecture details or compiler internals, they achieve microsecond-level real-time performance comparable to C++.
  • Seamless Strategy Deployment:The same codebase spans from strategy research through production deployment. This eliminates the need for strategy “translation” during go-live, ensuring behavioral consistency between backtests and live trading while dramatically shortening development cycles.
  • High Development Productivity:Built-in components such as order book synthesis engines and reactive streaming frameworks enable developers to rapidly implement core functionality like order aggregation — without building fundamental infrastructure from scratch.
  • Flexible Integration and Deployment: Swordfish can be embedded as a third-party library into existing systems like trading gateways, supporting diverse deployment architectures and significantly reducing migration costs.

Core Logic and Practical Implementation of DolphinDB Low-Latency Optimization

Through concrete technical implementations, code examples, and performance benchmarks, we systematically analyze Swordfish’s architecture across two key dimensions — low-level design optimization and scripting engine optimization — revealing how a scripting language can truly deliver C++-level performance.

I. Low-Level Design Optimization: Eliminating Latency at the Source

Low-latency performance is fundamentally determined by system design. Swordfish addresses latency bottlenecks at their root through several core architectural decisions, eliminating the inherent overheads of traditional approaches.

Row-Oriented Data Structures

Traditional columnar engines are poorly suited for real-time processing of individual or small batches of records. Swordfish adopts a row-oriented data layout, packing multiple fields of a single record into 64-byte cache-line–aligned runtime tuples. For example, a tuple containing id, value, flag, and timestamp is structured to perfectly align with CPU cache lines. This design dramatically reduces cache misses and delivers memory access performance on par with native C++ structs.

Custom Memory Pools to Eliminate Dynamic Allocation

Memory allocation is a hidden performance killer in low-latency systems, often introducing unpredictable jitter. Swordfish eliminates this instability through three strategies:

  • No allocation or deallocation in the critical path
  • Pre-allocation with controlled expansion
  • Custom PMR-based memory pools

By completely avoiding runtime memory requests to the operating system during main execution flows, Swordfish eliminates latency fluctuations at the source.

Cache-Friendly Data Structures

Order book engines rely heavily on ordered mappings and frequent traversal operations. Rather than using red-black tree–based map structures with scattered memory layouts, Swordfish employs flat_map, which stores data in contiguous memory. While insertion performance decreases slightly, lookup performance improves by 40–100%, and traversal performance increases by an order of magnitude—making it ideal for snapshot aggregation and real-time order book generation.

Smart Pointer Optimization

Conventional shared_ptr introduces overhead through double memory allocation and atomic reference counting. Swordfish replaces this with intrusive smart pointers (intrusive_ptr), embedding the control block directly into the object header so that object creation requires only a single allocation. Additionally, a single-threaded variant uses non-atomic reference counters to completely eliminate synchronization overhead and further reduce latency jitter.

Through these four foundational optimizations — row-based tuples, custom memory pools, flat_map data structures, and intrusive smart pointers—Swordfish systematically removes latency risks across data layout, memory management, data structures, and pointer handling.

Built on this robust low-level foundation, targeted scripting engine optimizations unlock additional hardware potential, enabling concise DLang scripts to consistently achieve C++-level execution performance in real-world microsecond-level low-latency systems.

II. Scripting Language Optimization: Enabling Dlang to Run at C++ Speed

The performance bottleneck of scripting languages typically stems from the inefficiency of interpreted execution. Swordfish overcomes this limitation through targeted optimizations in the scripting engine, dramatically improving execution efficiency while preserving the simplicity and expressiveness of DLang. As a result, DLang scripts achieve performance on par with native C++. The key optimization strategies fall into three areas:

Streamlined Control Flow

Swordfish simplifies script execution paths by eliminating unused intermediate variables and redundant states, thereby shortening the critical computation pipeline.

For example, in indicator calculations, scripts often define multiple intermediate variables step by step. After optimization, these operations are merged into a single expression that directly returns the result, significantly reducing unnecessary computation and interpretation overhead.

In-Place Computation Optimization

Interpreted execution frequently generates temporary objects, leading to repeated memory allocation and deallocation. Swordfish addresses this through schema inference in the streaming engine:

  • Operand types are inferred in advance
  • Result buffers are pre-allocated
  • Computation results are written directly into pre-allocated memory

This in-place computation model completely eliminates the cost of creating and destroying intermediate results, effectively reducing both latency and jitter.

Type Specialization Optimization

For core DLang operators (+, -, *, /) and commonly used functions such as rowSum and rowMax, Swordfish provides type-specialized implementations.

Through compile-time type inference, the engine selects the appropriate implementation before execution, eliminating runtime type checks and virtual function dispatch. The generated instruction sequences are therefore equivalent to hand-written C++, delivering substantial performance gains at the lowest level.

Performance Validation in Practice

The effectiveness of these optimizations is clearly demonstrated in real-world benchmarks. Using KDJ indicator calculation as an example:

Traditional C++ implementation:

  • ~334 lines of core code
  • Per-record latency: 3–7 microseconds

Optimized DLang implementation:

  • Only 6 lines of core code
  • Per-record latency: 1.49–3.70 microseconds

This represents a code reduction of over 98%, while achieving better performance than the C++ implementation — a compelling demonstration of how Swordfish enables scripting languages to break through traditional performance boundaries.

III. Empirical Performance Validation: Clear and Compelling Results

Extensive benchmark testing validates the effectiveness of Swordfish’s optimizations. All tests were conducted on an Intel i9–14900KS (5.4 GHz) CPU using 10 minutes of Level-2 market data.

Baseline Indicator Computation

Basic column-based indicators:

  • Average latency: 1.07 μs
  • P99 latency: 1.23 μs

Custom indicators (e.g., KDJ):

  • Average latency: 1.49 μs
  • P99 latency: 1.67 μs

These results demonstrate consistently low latency with tight tail behavior, even for complex custom indicators.

Multi-Indicator Concurrent Computation

  • Incremental latency per additional basic indicator: ~50 ns
  • Incremental latency per additional custom function: ~400 ns
  • 108 Level-2 custom factors:Average total latency: 42.7 μs. More than 2× faster than traditional C++ implementations under the same workload

This demonstrates excellent scalability when computing large numbers of real-time factors.

Concurrency and Stability

As concurrency increases from 1 to 6 streams:

  • Average latency rises only slightly from 42.7 μs to 44.4 μs
  • 99th percentile latency remains within 49.2 μs
  • Deviation between median and mean latency stays below 3%

Conclusion: High Performance Without the Cost of Complexity

At its core, low-latency engineering is not about writing increasingly complex code — it’s about designing systems where performance emerges naturally from the architecture. Swordfish demonstrates that achieving microsecond-level latency doesn’t require sacrificing developer productivity or relying on highly specialized C++ implementations. Through cache-aware data layouts, deterministic memory management, and execution-engine optimizations, concise DLang scripts can fully unlock modern CPU performance.

More importantly, these capabilities extend beyond theoretical benchmarks. They’ve been validated in real-world workloads involving Level-2 market data, large-scale factor computation, and concurrent execution scenarios. Developers can move from research to production using a single codebase — with fewer lines of code, lower cognitive overhead, and predictable, low-jitter microsecond latency in production environments.

When scripting productivity and native-level performance are no longer mutually exclusive, the engineering paradigm for low-latency systems fundamentally shifts. Swordfish represents not just a set of optimizations, but a design philosophy that makes high-performance systems both accessible and sustainable.
