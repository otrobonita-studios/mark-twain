I Could Do This AI Day​
We do find humour in exploring LLM benchmarking in an article dedicated to an ancient GTX 1080 Ti; however, what better way to illustrate the advancements in the GPU space that impact LLM inference performance today?
In this project, we focused on using 
llama.cpp
 for our LLM inference benchmarking. Llama.cpp is arguably the most popular backend for running models, and many AI software applications run on it. You can find forks or binaries for them in projects like 
Ollama
, 
Jan AI
, and 
LM Studio
. The llama.cpp project conveniently includes an easy-to-use benchmarking utility called llama-bench.
Llama-bench is considered a synthetic test because it uses nonsense tokens for its two tests: prompt processing (pp) or prefill, and text generation (tg). The benchmark doesn't prompt a model with recognizable English; it instead generates random tokens. Nevertheless, it doesn’t matter if we are using the first few paragraphs from Charles Dickens’ 
Tale of Two Cities
 or an equivalent amount of gibberish; the LLM (the math) doesn’t care what the tokens are; a forward pass through the model is a forward pass, regardless of the prompt's content.
The velocity of the prefill stage largely depends on a GPU’s compute power, as it is highly parallelized. Higher core counts, all of which can work simultaneously, will traditionally result in higher throughput, but this isn’t always the case. CUDA and Tensor core counts across NVIDIA cards can suggest a picture of performance, but generational improvements must be considered when comparing cards on specifications alone.
Success in text generation usually correlates with a graphics card’s memory bandwidth, because generating a token means reading the entire model from VRAM, and the GPU spends most of its time waiting on memory between generating each token. That being said, compute can be a bottleneck if the processor can’t chew through the data as fast as the memory can serve it up.
To replicate different use cases, we can control the following variables.
The size of the prompt in tokens (
-p
)
The size of the KV cache (context) (
-d
)
The number of tokens to generate (
-n
)
The size of the prompt (
-p
) only affects the prefill test, as the text generation test skips tokenization. Conversely, the number of tokens to generate (
-n
) is not used in the prefill stage, as no text generation occurs. The starting size of the KV cache affects both tests and represents tokens that have already been processed. By setting this flag, we can approximate what prefill and text generation performance would look like in the middle of a chat; setting 
-d
 to 0 would provide fresh context or start a new chat.

As we suspected, the GTX 1080 Ti gets obliterated in prompt processing. The GTX 1080 Ti has the same number of CUDA cores (albeit older architecture) as the RTX 3060, but the RTX 3060 has the Tensor core advantage. Tensor cores are dedicated matrix-multiply hardware designed to accelerate tasks like this.
Text generation performance isn’t as dire thanks to the decent 484 GB/s of memory bandwidth of the GTX 1080 Ti. The RTX 3060 has less bandwidth at 360 GB/s, yet, as explained earlier, memory bandwidth isn’t the be-all and end-all if you don’t have the processing to use all that runway. The RTX 3060 can generate tokens faster because it can use more of its memory bandwidth than the GTX 1080 Ti can.

The story is the same here too. If you chat with a model running on a GTX 1080 Ti, your time to first token will be horrendous compared to that of the RTX 3060 Ti (as indicated by the prefill speed), but the response generation speed won’t feel as archaic.
The GTX 1080 Ti has two things against it: maimed FP16 throughput and age-induced deprecation. The former is an example of NVIDIA’s notorious reputation for maintaining a market segmentation between consumer and datacenter/workstation products.
Undermined FP16 throughput
The GP102 processor on the GTX 1080 Ti has hamstrung FP16 throughput compared to the GP100 found on the P100 Tesla. The 
GP100 was designed for training neural networks and supports 2x FP16 throughput compared to FP32
. The GP104’s (largely similar to the GP102)  FP16 performance is 64 times slower than that of FP32 calculations. The GP102 and GP104 provide INT8 support that is not available on the GP100. You could get decent inference performance on the GTX 1080 Ti, but you needed to step up to a P100 Tesla with its GP100 to get any appreciable FP16 throughput. NVIDIA intended a product line for neural network training based on the GP100, and another line for inference based on the GP 102/104.
One thing going for the GP102 is its integer throughput. The token generation performance shown above largely stems from the specialized instructions for two- and four-way integer dot products (DP4A). This allows the GP102 to perform fast 8-bit integer math, which is exactly what quantized GGUF models use. When running the Q4 models above, llama.cpp doesn't convert the weights to floating-point numbers to do the math; it converts everything to 8-bit integers, taking advantage of the DP4A instructions. Modern Tensor core-laden GPUs still use the DP4A instructions today, albeit on newer, faster CUDA cores and faster memory.
Outdated Hardware
There’s no getting around it: Pascal is old news, the toolkits and drivers that support it have been deprecated and replaced. There are technologies being built around hardware (Tensor cores) that Pascal doesn’t even have: 
flash attention
. Llama.cpp supports flash attention on Pascal architecture but it's a second-class citizen.
Flash Attention is built around 
MMA/WMMA
 instructions, which are only expressed through a Tensor Core. Llama.cpp will fall back to pathways that work on Pascal, but in most cases, performance actually drops when flash attention is enabled, or it just doesn’t work.  
The GTX 1080 Ti only supports up to CUDA 12.x and 
Compute Capability 6.0/6.1
. In April this year, PyTorch (a popular Python framework) will introduce 
CUDA 13.2 and deprecate CUDA 12.8
. As time marches on, Pascal support will only get worse.
Conclusion
The GTX 1080 and 1080 are legends, there's no doubt about that. They earned their place in the hall of fame alongside other legends like the AM4 socket and the Core i7-8700K. Yet, their age is showing in gaming and AI workloads. 
NVIDIA promised that ray tracing would be the future of rendering; it's not, but the adoption of the technology is spreading. New games and even benchmark tools like 
Evolve
 expect your hardware to support ray tracing, which leaves the GTX lineups out.
Ray tracing aside, the Pascal GeForce graphics cards were hampered in the early days of neural network development. NVIDIA would much rather you spend much more money on products like the 
Tesla P100
 and 
Tesla P40
 in fact, they still prefer you buy the workstation cards for AI work. Nevertheless, if you have a GTX 1080 Ti lying around, it is certainly capable of enabling you to tinker with 8B- to 12B-parameter models.
If you are still rocking a GTX 1080 TI as your daily driver, we salute you.
