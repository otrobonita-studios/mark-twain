Writer

  • Paragraph directions for RTL text are now automatically detected when opening or pasting plain text (Jonathan Clark, TDF) tdf#157037
  • Read and re-export “hidden” and “show in gallery” properties of styles in the DOCX files. Allowing to filter list of styles to only meaningful ones. (Szymon Kłos, Collabora) 5bee91d5
  • Start is now the default paragraph alignment setting in new documents. (Jonathan Clark, TDF) tdf#169035
  • Changing paragraph directions no longer mirrors alignment of left- or right-aligned paragraphs. For paragraphs that are automatically aligned based on writing direction, please use start or end alignment. (Jonathan Clark, TDF) tdf#165206
  • Improved deleted commented text ranges in Writer’s DOCX filter. blog post (Miklos Vajna, Collabora)

Chart

  • LibreOffice now provides rudimentary support for import and re-export of new ("chartex") chart types that can be created in Microsoft Office and saved in OOXML formats. Chart types with this basic round-trip support include box-whisker, funnel, Pareto, sunburst, treemap, and waterfall charts. Region map charts contain extensive geographic information that is not supported, so while the chart type is preserved through round-trip, little substantial content is. No support exists yet for displaying or editing these chart types. Instead, a message is displayed to indicate that the chart type is not yet supported in LibreOffice. (Kurt Nordback, Collabora) tdf#165742

Scripting

Python

Users can create and edit Python scripts directly from Macro manager dialog without APSO installing, the buttons are active for actions now. The Python scripts will be opened in standard text editor on all OS. (Neil Roberts, TDF) tdf#56289

Scripts can create instances of UNO services using a constructor instead of having to use a string. (Neil Roberts, TDF) tdf#171122

For example: 

from com.sun.star.awt import Toolkit
toolkit = Toolkit.create(self.xContext)

Similarly for singletons: 

from com.sun.star.frame import theDesktop
desktop = theDesktop.get(ctx)

Users debugged remote processes to LibreOffice - started with officehelper.py - can be released from memory. Information is available from [Developer's Guide - Getting started] chapter. (Alain Romedenne) tdf#163465 

from officehelper import SessionManager
def my_script():
  # user code goes here

g_exportedScripts = (my_script,)  # LibreOffice entry points

if __name__ == "__main__":  # entry point for IDEs   
  with SessionManager() as ctx:  # remote Python context
    my_script()

The ScriptForge libraries

An extensible and robust collection of macro scripting resources for LibreOffice to be invoked from user Basic or Python scripts. (Jean-Pierre Ledure)

The libraries expose a total of 35 services each with a bunch of methods and properties.

New in LibreOffice 26.8:

  • The new ui.EnterValue(...) method displays a typed input box (cfr. the InputBox() Basic function) to the user and returns the entered value as a scalar of the requested type, or Empty/None when the user cancels the box. The supported types are: STRING, PASSWORD, BOOL, INTEGER, FLOAT, DATE, TIME, DATETIME, COMBO, LIST and RADIO.
  • (Basic only) The new array.Map(), array.Filter() and array.Reduce() methods introduce functional programming techniques on Basic arrays. They mimic their Python equivalents. Those methods allow the programmer to write simpler, shorter code, without necessarily needing to bother about intricacies like loops, branching and error handling.
  • The new session.GetUnoProperty() and session.GetPropertyByName() methods return the property value of resp. a UNO object or a ScriptForge service instance when the property name is given as a string.
  • (Python only) Python scripts may run either (1) inside the LibreOffice process, the usual mode, or (2) as a client of a LibreOffice server using a pipe or a socket. The benefit of (2) is the freedom to choose his/her preferred IDE to edit and debug the script. The drawback is the reference to the pipe/socket in the script source code. Avoid this by using a default pipe, named PIPE2LIBREOFFICE. The same code will run without change in both (1) and (2) modes.

The whole set of services (except when better done by native built-in functions) is made available for Python scripts with identical syntax and behavior as in Basic.

ScriptForge in the wiki: read Macros/ScriptForge (Lobaluna).

The English version of the documentation of the ScriptForge libraries (26.8) is partially integrated in the LibreOffice help pages (https://help.libreoffice.org/26.8/en-US/text/sbasic/shared/03/lib_ScriptForge.html?DbPAR=BASIC). Their finalization and translation into other languages is underway. (Alain Romedenne, Lobaluna)
