A bundler for 1999's geometry

Now the 3D part, from zero.

A GoldSrc-era map â the format behind Half-Life and the original Counter-Strike â is not a soup of triangles. It is a 
BSP
 file: the level's polygons stored pre-organized into a 
binary space partitioning tree
, a 1990s data structure that recursively slices the world with planes until every position falls into a convex cell called a 
leaf

PVS â the Potentially Visible Set
. For every leaf, the file stores a precomputed, compressed bitset of every other leaf that could 
ever

If you want this in web terms: the PVS is occlusion culling as a lockfile. All the expensive thinking happened offline, and the runtime just looks up the answer. Standing in the dust2 courtyard, the renderer never even considers the tunnels' geometry â not "draws it fast," but 
never touches it

We kept that 1999 spirit and extended it with a modern move: 
treat the console like a deploy target and put a compiler in front of it.
 The PSP cannot afford to parse a BSP file, decode textures, or reshape data at load time â that costs RAM for intermediate copies and CPU we would rather spend on bots. So OpenStrike's build step runs

"Baking" is the word for moving runtime cost to build time, and the cooker bakes aggressively:

Lighting is baked into vertex colors.
 GoldSrc maps ship

 â little per-surface shadow textures. The GE could multitexture them, but every texture unit costs bandwidth we would rather not spend. So the cooker dices each polygon into a grid and 
samples the lightmap into the vertices' color channel

Positions are quantized to 16-bit integers.
 Half the memory and half the GPU-read bandwidth of floats. (This unlocked the port's favorite piece of hardware archaeology: in 3D mode the GE silently 
normalizes

Textures become CLUT8

The payoff for all this build-time obsession is the load screen we don't have: the

If you have used PocketJS, this is the same ideology that compiles Tailwind classes to a binary style table and bakes fonts to atlases â 
the device never parses, it only consumes

The texture glow-up, or: the machine hides nothing

Midway through the port we noticed the textures looked muddier than 1999 deserved, and the investigation is a nice showcase of how unforgiving â and how 
legible
 â this hardware is. Three independent causes, all in the pipeline above:

The same crate, before and after, 3Ã crop of the PSP framebuffer. Left: nearest-neighbor resampling, round-down sizing, default mip selection. Right: bilinear palette-aware resampling, round-up sizing, â1.0 mip bias, and a 2Ã denser light grid.
First, non-power-of-two textures (a 96Ã96 crate face, say) were being stretched to GPU-legal sizes with nearest-neighbor sampling, which duplicates texel columns in a visibly irregular rhythm. The fix is a bilinear resample â but through a

nearest

Third, the GE has no anisotropic filtering, and its automatic mip selection goes blurry on floors at glancing angles long before texel density demands it â a â1.0 LOD bias holds the sharp mip one distance ring longer, a trade every PSP-era shipped game quietly made. And while we were in there, the light-bake grid tightened from 96 world units to 32 â every other lightmap sample â so baked shadow edges snap back into place. Dust2 went from 26k to 58k vertices and the map grew 0.9 MB, which the budget absorbed without a flinch, as the next section shows.

Determinism is the debugger

How do you debug a machine with no console, no debugger UI, and no screen-sharing? You make the program a 
pure function

OpenStrike inherits PocketJS's closed-world rules: a fixed 1/60 s timestep, no wall clocks, seeded randomness, and per-frame input that is just a button bitmask plus two analog bytes. Frame N is a pure function of the input script â so a scripted run produces

byte-for-byte

What this actually proves

The Pocket runtime family's thesis is that a 
product

The desktop build: same rules.ts, same hud.tsx, same crates â eleven times the pixels and per-pixel lightmaps, because that engine can.
Nothing about the pattern is PSP-specific. The console is, as we said when introducing PocketJS, an honest referee: a machine that will not quietly absorb a lazy architecture. An FPS with its brains in TypeScript holding 60 FPS
